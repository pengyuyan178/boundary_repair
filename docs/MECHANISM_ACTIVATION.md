# 第4项：三层机制执行链

基于已验证提交 `2ce14ad10048cdd6360a1201dae8da3a538b9d79`。本轮范围为局部条件/规则和组件属性/消费通路，保留单向流程、一次证据请求、最多一次代码生成及独立评测。现有SEARCH/REPLACE、语法、源码哈希和进程隔离继续生效。

## 证据与程序目录

`ProgramPort.observation_scenarios` 从修复前程序的声明输入类型、源码常量和局部路径条件构造有限入口情境。每个情境包含稳定ID、观察接口、完整输入、条件和来源类型，不包含预期输出。布尔接口使用声明的布尔域；其他标量使用源码已有同类型常量。枚举最多检查每个接口256组赋值，总目录最多2048项。这是明确受限的局部入口集合，不代表真实UI状态已经被执行或穷尽。

`evidence.v6` 保留原始观察、需求解释组和FRAME，改用每条声明的 `binding_alternatives:[{cases:[{scenario_id,expected}]}]`。同一个备选中的情境是合取，不同备选是对应关系歧义。空备选保留未确定对应。程序解析情境ID并校验类型及源码引用，模型不再填写参数列表或证明标志。单条声明所有备选合计最多16个不同入口；无来源的绑定不被接受。

需求、绑定和证书具有不同含义：明确的需求仍可能未绑定；绑定成立不证明模型理解图片正确；局部入口可满足不证明浏览器可达。OBSERVATION不能产生目标入口，FRAME必须有正向保持依据。旧v3/v4/v5解析入口保留供档案读取，不会给旧响应自动补情境。

## 部分规格与局部证明

需求解释和程序绑定备选共同进入有限接受理论；共有的源绑定命题按规范逻辑形状归一化。没有可靠绑定的自然语言声明保留其独立文本身份。MUST/MAY相对于该理论计算，矛盾与求解上限不能成为证明。

`ContractSet.bindings` 保存候选对应，`BehaviorConstraint.binding_alternatives` 保存歧义。只有解释共有的入口进入无条件见证。未绑定的MUST不再抹掉其他入口的局部证明。

正证书附带实际有限语法构造，负证书只排除相同源码位置、读取接口和修改语法；未找到构造仍为UNKNOWN。`InterfaceCertificate` 保存覆盖义务、输入、允许输出、源码及摘要哈希、接口ID、读取特征和规格策略。不同语法节点或读取方式具有不同候选ID。

程序支持原有纯标量投影、显式布尔短路JSX构造及不影响观察的无副作用死局部声明。潜在调用、副作用、异步、getter/proxy等仍遵循声明前提或返回UNKNOWN，不据此证明完整浏览器行为。

## 作用域与编译

全部硬义务联合通过且修复前存在不符时，选择 `certified_projection` 并编译固定构造。只有部分义务可验证时，可选择 `guided_partial`：保留未解决需求及原有普通编辑能力，提供局部构造建议，并将已验证属性登记为 `PatchPlan.enforced_obligations`。

最终事务通过既有唯一SEARCH/REPLACE匹配和源码权限检查后，程序对实际修改结果重新解析，重验已登记属性。源码观察位置、函数头和声明绑定必须仍能对应；无法重建对应关系或已证明属性被违反时拒绝事务，不增加生成次数。完整证书路径仍要求实际事务与固定构造一致。

成功编译记录 `trajectory/transaction_semantics.json`，绑定最终补丁哈希与实际属性检查；拒绝记录 `rejected_semantics.json`。计划中的检查通过不能代替最终事务检查。语义成本保持 `(U_req,U_frame,R_protected,S_extra,N_invented,N_AST)` 字典序；未知影响不算零风险，新引入标量常量按原/新属性表达式比较。

## 独立模块开关

- 关闭第一层：按固定顺序采用第一项有来源解释及绑定，保留后续需要的规格和见证。`specification_policy=first_sourced_interpretation` 明确说明这些是对照假设，不是MUST蕴含结论；证书沿用该条件范围。
- 关闭第二层：共用候选池，只做相关性排序，不产生正负定位证书。第三层可使用公共摘要构造并联合验证计划，但不伪造第二层证书。
- 关闭第三层：消费前序定位输出，普通生成一次，不进行语义成本优化。

图片、检索、模型、预算、语法与隔离条件对所有组合一致。工程测试中的脚本模型仅验证交接，不代表真实模型质量。

## 离线验证入口

完整回归在4090既有固定Docker镜像中运行 `python -m unittest discover -s tests -v`，固定seed42，无网络。正式dev生成和评分等待五类问题全部修复后统一安排。

`scripts/replay_mechanisms.py` 提供两段入口：准备端只读取已净化任务、历史证据和生成前作用域，从完整存档或既有精确base提交缓存恢复源码并核对哈希；分析端在无网络、无答案挂载的Docker中运行。原证据目录按旧请求编号恢复，逐段核对实际源码。所有100题登记，缺失证据不从清单中删除；可用证据全部重放。

离线模型入口直接禁止调用，不编译或输出新补丁。报告保存前后接口、绑定、判定、计划和权限差异。新增可供关联的情境数不等于已得到真实模型关联；历史空绑定仍为空。工程通过与历史重放均不能证明新的修复率或超过baseline。
